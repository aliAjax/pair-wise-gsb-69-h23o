# 数据中心变更窗口与回滚方案审阅平台

面向机房运维、系统、安全和业务负责人的生产变更审阅工作台。工程使用 Angular CLI 独立构建，所有变更记录会写入浏览器 `localStorage`，首次运行通过 `HttpClient` 加载 `public/mock/change-requests.json`。

## 技术栈

- Angular 22 + Angular CLI + TypeScript
- Clarity Angular 18 + Clarity UI
- NgRx Store + Effects
- Angular Router + HttpClient
- RxJS

## 功能

- 变更列表搜索，以及按状态、资源类型和风险等级筛选
- 新建变更方案，维护资源、依赖、执行步骤、回滚步骤、值守人员和窗口
- 依赖关系图与共享资源窗口甘特图
- 依赖遗漏、窗口冲突、回滚不可执行、关键服务观察窗口不足校验
- 网络、系统、安全、业务负责人顺序会签
- 执行步骤勾选、实时日志入口、执行偏离记录、完成或回滚判定
- 控制台与机房值守**双端事件账本**：两端各持一份记录，按变更版本、步骤编号和发生时间对账；一致事件幂等合并，载荷相异挂冲突待复核
- 窗口或资源依赖变化后版本/纪元递增：未确认事件先失效再重新确认，已成立的操作仍可从合并账本重放还原
- 断网与写入故障演练：事件先进发件箱，恢复后重试并续作；完成或回滚结论只从同一份合并结果推导
- 审批冻结、审计轨迹和复盘 Markdown 导出（含完整事件流与冲突复核记录）
- 基于 NgRx 的状态流转与 localStorage 持久化

```bash
npm install

```

生产构建：


## 双端事件账本

执行开始后，控制台（console）与机房值守（onsite）两端各维护一份事件记录，所有步骤勾选、执行偏离、完成/回滚判定都以事件提交：

1. **对账**：事件对账键为 `变更版本 | 事件类型 | 步骤编号 | 发生时间`。两端同键且载荷一致时幂等合并，不会互相冲掉；同键但载荷相异时双方事件置为“冲突待复核”，完成与回滚结论暂不成立，由复核人采纳其中一方或双方舍弃后再重放。
2. **审批冻结照旧**：开始执行时会签内容冻结，事件账本不修改任何审批字段。
3. **窗口/资源依赖变化**：版本与纪元递增，`pending`（未确认）事件先变为失效并可在新版本上“重新确认”；`committed`（已成立）的操作不受影响，随时可“从合并账本还原”。
4. **断网与写入失败**：事件先进入发件箱（未确认）。离线或写入故障时保留在发件箱，恢复在线或关闭故障后“重试并续作”，幂等标识保证不重复入账。
5. **单一事实来源**：步骤状态、偏离列表与最终完成/回滚状态全部由 `projectLedger` 重放同一份合并账本得出，不能由单次操作直接写入。

执行页提供“端在线”开关和“模拟写入故障”开关用于演练断网重连与写入重试。
